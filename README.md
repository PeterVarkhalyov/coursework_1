# Курсовая работа №1

## Вступление
Курсовая работа №1 состоит в разработке приложения для анализа транзакций, 
которые находятся в Excel-файле. Приложение должно генерировать JSON-данные для
веб-страниц, формировать Excel-отчеты, а также предоставлять другие сервисы.

## Условия выполнения
Задачи по категориям:
1. Веб-страницы:
   - Главная
   - События
2. Сервисы:
   - Выгодные категории повышенного кешбэка
   - Инвесткопилка
   - Простой поиск
   - Поиск по телефонным номерам
   - Поиск переводов физическим лицам
3. Отчеты:
   - Траты по категории
   - Траты по дням недели
   - Траты в рабочий/выходной день

### Функциональные требования
#### Веб-страницы
Основные функции для генерации JSON-ответов реализуйте в отдельном модуле 
`views.py`.

##### Страница «Главная»
Реализуйте набор функций и главную функцию, принимающую на вход строку с датой 
и временем в формате `YYYY-MM-DD HH:MM:SS` и возвращающую JSON-ответ 
со следующими данными:
1. Приветствие в формате "???", где 
??? — «Доброе утро» / «Добрый день» / «Добрый вечер» / «Доброй ночи» в 
зависимости от текущего времени.
2. По каждой карте:
    - последние 4 цифры карты;
    - общая сумма расходов;
    - кешбэк (1 рубль на каждые 100 рублей).
3. Топ-5 транзакций по сумме платежа.
4. Курс валют.
5. Стоимость акций из S&P500.

##### Страница «События»
Реализуйте набор функций и главную функцию, принимающую на вход строку с датой 
и второй необязательный параметр — диапазон данных. По умолчанию диапазон 
равен одному месяцу (с начала месяца, на который выпадает дата, по саму дату).

Возможные значения второго необязательного параметра:
- `W` — неделя, на которую приходится дата;
- `M` — месяц, на который приходится дата;
- `Y` — год, на который приходится дата;
- `ALL` — все данные до указанной даты.

Возвращаемый JSON-ответ содержит следующие данные:
1. «Расходы»:
   - Общая сумма расходов.
   - Раздел «Основные», в котором траты по категориям отсортированы по убыванию. Данные предоставляются по 7 категориям с наибольшими тратами, траты по остальным категориям суммируются и попадают в категорию «Остальное».
   - Раздел «Переводы и наличные», в котором сумма по категориям «Наличные» и «Переводы» отсортирована по убыванию.
2. «Поступления»:
    - Общая сумма поступлений.
    - Раздел «Основные», в котором поступления по категориям отсортированы по убыванию.
3. Курс валют.
4. Стоимость акций из S&P 500.

#### Сервисы
Реализуйте сервисы в отдельном модуле `services.py`.
При реализации сервисов должны использоваться элементы функционального 
программирования.

##### Выгодные категории повышенного кешбэка
Сервис позволяет проанализировать, какие категории были наиболее выгодными 
для выбора в качестве категорий повышенного кешбэка.

##### Инвесткопилка
Позволяет копить через округление ваших трат.
Можно задать комфортный порог округления: 10, 50 или 100 ₽. Траты будут 
округляться, и разница между фактической суммой трат по карте и суммой 
округления будет попадать на счет «Инвесткопилки».

##### Простой поиск
Пользователь передает строку для поиска, возвращается JSON-ответ со всеми 
транзакциями, содержащими запрос в описании или категории.

###### Поиск по телефонным номерам
Функция возвращает JSON со всеми транзакциями, содержащими в описании 
мобильные номера.

###### Поиск переводов физическим лицам
Функция возвращает JSON со всеми транзакциями, которые относятся к переводам 
физлицам.

Категория такой транзакции — `Переводы`, а в описании есть имя и первая буква 
фамилии с точкой.

#### Отчеты
Реализуйте отчеты в отдельном модуле `reports.py`.
Создайте декоратор для функций-отчетов, который записывает в файл результат, 
который возвращает функция, формирующая отчет.
- Декоратор без параметра — записывает данные отчета в файл с названием 
по умолчанию (формат имени файла придумайте самостоятельно).
- Декоратор с параметром — принимает имя файла в качестве параметра.

##### Траты по категории
Функция принимает на вход:
- датафрейм с транзакциями,
- название категории,
- опциональную дату.

Если дата не передана, то берется текущая дата.

Функция возвращает траты по заданной категории за последние три месяца 
(от переданной даты).

##### Траты по дням недели
Функция принимает на вход:
- датафрейм с транзакциями,
- опциональную дату.

Если дата не передана, то берется текущая дата.

Функция возвращает средние траты в каждый из дней недели за последние 
три месяца (от переданной даты).

##### Траты в рабочий/выходной день
Функция принимает на вход:
- датафрейм с транзакциями
- опциональную дату.

Если дата не передана, то берется текущая дата.

Функция выводит средние траты в рабочий и в выходной день за последние 
три месяца (от переданной даты).

## Установка проекта с GitHub

1. На странице репозитория GitHub нажмите **Code** и скопируйте HTTPS-адрес.
2. Клонируйте репозиторий, заменив `USERNAME/REPOSITORY` на данные проекта:

   ```shell
   git clone https://github.com/USERNAME/REPOSITORY.git
   ```

3. Перейдите в каталог проекта:

   ```shell
   cd REPOSITORY
   ```

4. Установите зависимости из `poetry.lock`:

   ```shell
   poetry install
   ```

5. Проверьте, что проект работает:

   ```shell
   poetry run pytest
   ```

Поскольку GitHub-адрес ещё не привязан к текущему локальному репозиторию,
`USERNAME/REPOSITORY` в примерах необходимо заменить на реальный адрес после
публикации проекта.

## Реализация условий

### Модуль `api_responses`
Модуль `src.api_responses` содержит общие вспомогательные функции для 
обращения к внешним API. Он отвечает за получение API-ключей из переменных 
окружения, выполнение HTTP-запросов и первичную проверку JSON-ответов.

При загрузке модуля:
- переменные окружения загружаются из файла .env;
- создаётся каталог logs, если он отсутствует;
- настраивается запись сообщений в файл logs/api_responses.log;
- для HTTP-запросов устанавливается тайм-аут 10 секунд.

#### `get_api_key`
Функция получает название переменной окружения и возвращает сохранённый в ней 
API-ключ.
Если переменная отсутствует или содержит пустое значение, функция записывает 
ошибку в журнал и возвращает None.

```python
get_api_key(code_key: str) -> str | None
```
Секретные ключи следует хранить в локальном файле `.env` и не добавлять его в 
репозиторий:

```
RATES_API_KEY=ваш_api_ключ
```

#### `get_response`
Функция выполняет `GET`-запрос по указанному адресу и передаёт параметры 
через строку запроса. Максимальное время ожидания ответа составляет 10 секунд.
Функция ожидает, что API вернёт JSON-объект в виде словаря. При успешной 
обработке этот словарь возвращается вызывающему коду.
```python
get_response(
    url: str,
    params: dict[str, str | float],
) -> Any | None
```
Если ответ невозможно преобразовать из JSON или его корневое значение 
не является словарём, функция записывает ошибку в `logs/api_responses.log` и 
возвращает `None`.
Ошибки соединения, превышение времени ожидания и другие исключения библиотеки 
`requests` передаются вызывающему коду. При необходимости их следует 
обрабатывать самостоятельно.

#### Логирование
Сообщения записываются в файл:
```text
logs/api_responses.log
```
Каждая запись содержит дату и время, имя логера, название функции, 
уровень события и текст сообщения. При новом запуске приложения 
предыдущие записи файла заменяются.

### Модуль `currencies`
Модуль `src.currencies` получает курсы валют из внешнего API, проверяет 
полученные данные и формирует список котировок в соответствии с 
пользовательскими настройками.

В качестве источника используется бесплатный сервис ExchangeRate-API:
```text
https://open.er-api.com/v6/latest/
```
Для работы с этим API ключ не требуется.

Настройки валют загружаются из файла `configs/user_settings.json`:
``` JSON
{
  "user_currency_quote": "RUB",
  "user_currencies": ["USD", "EUR", "CNY", "TRY"]
}
```
Параметры имеют следующее назначение:
- `user_currency_quote` — базовая валюта, в которой должны быть представлены 
котировки;
- `user_currencies` — список валют, курсы которых необходимо получить.

#### `get_currency_rates`
```python
get_currency_rates() -> list[dict[str, Any]] | None
```
Основная публичная функция модуля. Она выполняет следующие действия:
1. Загружает настройки из `configs/user_settings.json`.
2. Получает курсы относительно базовой валюты.
3. Рассчитывает обратные курсы для валют пользователя.
4. Округляет полученные значения до двух знаков после запятой.
5. Возвращает список словарей с кодами валют и их курсами.

Структура результата:
```JSON
[
    {
        "currency": "USD",
        "rate": 00.00,
    },
    {
        "currency": "EUR",
        "rate": 00.00,
    },
]
```
Значение `rate` показывает стоимость одной единицы соответствующей валюты в 
базовой валюте. Например, при `user_currency_quote: "RUB"` результат 
содержит стоимость одного доллара, евро или юаня в рублях.
Если настройки отсутствуют, список валют пуст, API недоступен или ответ 
содержит некорректные данные, функция возвращает `None`.

#### `_get_currency_rates_from_api`
```python
_get_currency_rates_from_api(
    currency_quote: str,
) -> dict[str, Any] | None
```
Внутренняя функция, которая запрашивает курсы относительно указанной 
базовой валюты.
Адрес запроса формируется добавлением кода валюты к базовому URL:
```python
https://open.er-api.com/v6/latest/RUB
```
Функция проверяет:
- наличие ответа от API;
- отсутствие сообщения об ошибке;
- наличие поля `rates`;
- соответствие поля `rates` типу `dict`.

При ошибке запроса или некорректном ответе функция записывает сообщение 
в журнал и возвращает `None`.

#### `_calculate_currency_quote`
```python
_calculate_currency_quote(
    currency: str,
    currency_rates: dict[str, Any],
    digit: int,
) -> dict[str, Any] | None
```
Рассчитывает обратный курс одной валюты и округляет результат до указанного 
количества знаков после запятой.

Котировка не формируется, если:
- валюта отсутствует в ответе API;
- курс имеет неверный тип;
- курс меньше или равен нулю;
- передано отрицательное количество знаков для округления.

В этих случаях функция возвращает `None`.

#### `_build_currency_quotes`
```python
_build_currency_quotes(
    user_currencies: list[str],
    currency_rates: dict[str, Any],
    digit: int,
) -> list[dict[str, Any]]
```
Формирует итоговый список котировок для всех валют пользователя. Валюты, 
для которых невозможно рассчитать корректный курс, пропускаются.

Функции, названия которых начинаются с символа подчёркивания, предназначены 
для внутреннего использования. Основной точкой входа модуля является 
`get_currency_rates()`.

#### Логирование
Информация о работе модуля записывается в файл:
```text
logs/currencies.log
```
Журнал содержит сведения о запросах к API, полученных курсах, ошибках 
настроек и некорректных данных. При новом запуске приложения предыдущее 
содержимое файла заменяется.

### Модуль `fields`
Модуль `src.fields` содержит вспомогательные функции для получения значений 
из словарей по именам полей и вложенным путям, работы со справочником 
псевдонимов и загрузки пользовательских настроек.
Модуль позволяет отделить внутренние названия полей приложения от названий 
столбцов исходного файла. Соответствие между ними хранится 
в `configs/field_aliases.json`.

Пример справочника:
```JSON
{
  "date_operation": [
    "Дата операции"
  ],
  "card_number": [
    "Номер карты"
  ],
  "amount_payment": [
    "Сумма платежа"
  ],
  "category": [
    "Категория"
  ],
  "descript": [
    "Описание"
  ]
}
```

Для одного внутреннего поля можно указать несколько возможных путей. При 
поиске используется первое найденное значение.

#### `get_by_path`
```python
get_by_path(
    item: Mapping[str, Any],
    path: str,
) -> Any
```
Получает значение из словаря по обычному ключу или вложенному пути, 
части которого разделены точками.

Если указанный ключ или вложенный путь отсутствует, функция создаёт 
исключение `KeyError`.

#### `get_field_value`
```python
get_field_value(
    transaction: Mapping[str, Any],
    field_name: str,
    field_aliases: Mapping[str, list[str]],
) -> Any
```
Находит значение поля транзакции с помощью справочника псевдонимов.

Функция получает:
- `transaction` — словарь с данными транзакции;
- `field_name` — внутреннее название поля;
- `field_aliases` — соответствие внутренних названий возможным ключам 
или путям.

Функция проверяет пути по порядку и возвращает первое найденное значение. 
Если поле отсутствует в справочнике либо ни один путь не найден в 
транзакции, возвращается пустой список.

#### `load_user_settings`
```python
load_user_settings(
    file_path: str | Path,
) -> tuple[list[str], list[str], str]
```
Загружает пользовательские настройки из JSON-файла.
Ожидаемая структура файла:
```JSON
{
  "user_currency_quote": "RUB",
  "user_currencies": [
    "USD",
    "EUR",
    "CNY",
    "TRY"
  ],
  "user_stocks": [
    "AAPL",
    "AMZN",
    "GOOGL",
    "MSFT",
    "TSLA"
  ]
}
```
Функция возвращает кортеж из трёх элементов:
1. список пользовательских валют;
2. список тикеров акций;
3. код базовой валюты.

Файл должен содержать все три обязательных поля. Если структура настроек 
некорректна или необходимый ключ отсутствует, функция создаёт исключение 
`KeyError` либо `TypeError`, которое должен обработать вызывающий код.

#### Логирование
Информация о поиске и загрузке полей записывается в файл:
```text
logs/fields.log
```
Журнал содержит сведения об отсутствующих ключах, не найденных вложенных 
путях и ошибках справочника. При новом запуске приложения предыдущее 
содержимое файла заменяется.

### Модуль `readers`
Модуль `src.readers` содержит вспомогательные функции для загрузки 
финансовых транзакций из Excel и чтения конфигурационных данных из 
JSON-файлов.
Для работы с Excel используется библиотека `pandas`. Поддержка форматов
`.xlsx` и `.xls` обеспечивается зависимостями `openpyxl` и `xlrd`.

#### `get_transactions_from_xls`
```python
get_transactions_from_xls(
    file_path: str | Path,
) -> list[dict[str, Any]]
```
Загружает финансовые транзакции из Excel-файла и возвращает их в виде списка 
словарей.

Названия столбцов становятся ключами словаря, а содержимое строки — значениями
соответствующей транзакции.

При обработке данных функция:
1. Открывает лист `Отчет по операциям`.
2. Преобразует таблицу в список словарей.
3. Пропускает полностью пустые строки.
4. Пропускает строки, содержащие только пустые или пробельные значения.
5. Возвращает список корректных записей.

Если Excel-файл отсутствует, повреждён, недоступен, пуст или не содержит 
листа `Отчет по операциям`, функция записывает информацию об ошибке 
в журнал и возвращает пустой список.

#### `get_fields_from_json`
```python
get_fields_from_json(
    file_path: str | Path,
) -> Any
```
Загружает данные из JSON-файла в кодировке `UTF-8`.

Корневым элементом JSON должен быть объект, то есть структура, которая 
преобразуется в словарь `Python`.

Функция возвращает пустой список, если:
- файл отсутствует или недоступен;
- содержимое невозможно декодировать как `UTF-8`;
- файл содержит некорректный `JSON`;
- корневой элемент `JSON` не является объектом.

#### Обработка ошибок
Обе функции обрабатывают ожидаемые ошибки чтения самостоятельно и 
возвращают пустой список. Это позволяет использовать единый способ проверки 
результата.

Неожиданные программные ошибки не подавляются и передаются вызывающему коду.

#### Логирование
Информация о загрузке файлов записывается в:
```text
logs/readers.log
```
Журнал содержит:
- путь к загружаемому файлу;
- количество успешно загруженных элементов;
- количество пропущенных пустых строк;
- описание ошибок чтения или формата данных.

При новом запуске приложения предыдущее содержимое файла заменяется.

### Модуль `processing_views`
Модуль `src.processing_views` загружает и подготавливает транзакции для
веб-страниц «Главная» и «События».

Основные функции модуля:
- `get_greeting(date_time)` — выбирает приветствие по времени суток;
- `get_transactions()` — загружает операции из `data/operations.xlsx`;
- `get_transactions_view(...)` — отбирает успешные расходы или поступления за
  неделю (`W`), месяц (`M`), год (`Y`) либо за всё время (`ALL`);
- `get_cards_summary(date_time)` — группирует расходы по банковским картам и
  рассчитывает сумму, кешбэк и количество операций;
- `get_top_transactions(date_time, count_top)` — возвращает крупнейшие
  транзакции по модулю суммы;
- `get_category_summary(...)` — группирует расходы или поступления по
  категориям, возвращает топ категорий, общую сумму и количество транзакций.

В результате `get_category_summary` каждая категория имеет структуру:
```json
{
  "category": "Супермаркеты",
  "amount": 15400.5,
  "count": 12
}
```

Категории сортируются по убыванию суммы. В результат попадает заданное число
крупнейших категорий, а сумма и количество транзакций всех оставшихся
категорий объединяются в элемент `Остальное`. Каждая оставшаяся операция
учитывается в нём ровно один раз.

Некорректные даты, суммы, категории и номера карт регистрируются в журнале и
пропускаются. Ошибки типов входных аргументов и отрицательное значение
`count_top` приводят к `TypeError` или `ValueError`.

Журнал работы модуля сохраняется в:
```text
logs/processing_views.log
```

### Модуль `views`
Модуль `src.views` формирует итоговые JSON-ответы веб-страниц:
- `get_main_response(date_time)` — приветствие, сведения по картам, топ-5
  транзакций, курсы валют и котировки акций для страницы «Главная»;
- `get_events_response(date_time, date_range)` — расходы и поступления по
  категориям с общими суммами и количеством операций, а также валютные и
  биржевые котировки для страницы «События».

Функции возвращают JSON-строки с сохранением кириллических символов.

### Модуль `stocks`
Модуль `src.stocks` отвечает за получение последних доступных котировок 
акций из внешнего API и преобразование их стоимости в выбранную 
пользователем валюту.

Для получения котировок используется Marketstack API:
```text
https://api.apilayer.net/marketstack/v2/eod/latest
```
Список акций и целевая валюта загружаются из файла 
`configs/user_settings.json`:
```json
{
  "user_currency_quote": "RUB",
  "user_stocks": [
    "AAPL",
    "AMZN",
    "GOOGL",
    "MSFT",
    "TSLA"
  ]
}
```
Параметры имеют следующее назначение:
- `user_stocks` — список тикеров акций;
- `user_currency_quote` — валюта, в которую необходимо пересчитать стоимость 
акций.

Для обращения к `Marketstack` требуется API-ключ. Модуль получает его из 
переменной окружения `RATES_API_KEY`:
```text
RATES_API_KEY=ваш_api_ключ
```
Файл `.env` с настоящим ключом не следует добавлять в репозиторий.

#### `get_stock_rates`
```python
get_stock_rates() -> list[dict[str, Any]] | None
```
Основная публичная функция модуля. Она выполняет следующие действия:
1. Загружает список тикеров и целевую валюту из `configs/user_settings.json`.
2. Получает последние доступные котировки через `Marketstack API`.
3. Получает необходимые валютные курсы.
4. Пересчитывает цены акций в выбранную валюту.
5. Округляет цены до двух знаков после запятой.
6. Возвращает сокращённый список котировок.

Структура результата:
```json
[
    {
        "stock": "AAPL",
        "price": 00000.00,
    },
    {
        "stock": "MSFT",
        "price": 00000.00,
    },
]
```
Поле `stock` содержит тикер акции, а `price` — её стоимость в 
валюте `user_currency_quote`.
Если настройки некорректны, список акций пуст, отсутствует API-ключ, 
внешний сервис недоступен или не удалось получить ни одной корректной 
котировки, функция возвращает `None`.

#### `_get_stock_rates_from_api`
```python
_get_stock_rates_from_api(
    stocks: list[str],
) -> list[dict[str, Any]] | None
```
Внутренняя функция для получения котировок из `Marketstack API`.
Она принимает список тикеров:
```python
stocks = [
    "AAPL",
    "MSFT",
    "TSLA",
]
```
Тикеры объединяются в одну строку и передаются сервису через 
параметр `symbols`:
```text
AAPL,MSFT,TSLA
```
API-ключ передаётся в параметре `access_key`.

Функция проверяет:
- что список тикеров не пуст;
- что переменная `RATES_API_KEY` содержит API-ключ;
- что API вернул данные;
- что в ответе отсутствуют поля `message` и `error`;
- что поле `data` является списком;
- что каждый элемент списка является словарём.

При успешном запросе возвращается список исходных котировок. При ошибке 
функция записывает сообщение в журнал и возвращает `None`.

#### `_convert_stock_price`
```python
_convert_stock_price(
    price: Any,
    source_currency: Any,
    target_currency: str,
    currency_rates: dict[str, Any],
    digit: int,
) -> float | None
```
Преобразует стоимость одной акции из исходной валюты в целевую.

Аргументы:
- `price` — исходная стоимость акции;
- `source_currency` — валюта исходной котировки;
- `target_currency` — требуемая валюта результата;
- `currency_rates` — словарь валютных курсов;
- `digit` — количество знаков после запятой.

Если исходная и целевая валюты совпадают, функция только округляет цену.

Если валюты различаются, цена пересчитывается по курсу, полученному через 
модуль `currencies`.

При отсутствии или некорректном значении `source_currency` исходной валютой 
считается `USD`.

Функция возвращает `None`, если:
- цена не является числом;
- цена отрицательная;
- необходимый валютный курс отсутствует;
- валютный курс имеет неверный тип;
- валютный курс меньше или равен нулю.

Значения типа `bool` не считаются допустимой числовой ценой.

#### `_calculate_stock_rates`
```python
_calculate_stock_rates(
    currency: str,
    stock_rates: list[dict[str, Any]],
    digit: int,
) -> list[dict[str, Any]] | None
```
Формирует расширенный список котировок в указанной валюте.

Функция:
1. Проверяет код целевой валюты.
2. Проверяет количество знаков после запятой.
3. Получает курсы валют относительно целевой валюты.
4. Последовательно обрабатывает каждую котировку.
5. Пропускает элементы с некорректной ценой или валютой.
6. Возвращает список успешно обработанных акций.

Для расчёта используется поле `adj_close` из ответа `Marketstack`. Исходная 
валюта определяется по полю `price_currency`. Если это поле отсутствует или 
содержит некорректное значение, используется `USD`.

Если список котировок пуст, параметры некорректны или ни одну котировку не 
удалось обработать, функция возвращает `None`.

Функции, названия которых начинаются с символа подчёркивания, 
предназначены для внутреннего использования. Основной точкой входа 
является `get_stock_rates()`.

#### Логирование
Информация о работе модуля записывается в файл:
```text

```
Журнал содержит:
- запрашиваемые тикеры;
- целевую валюту;
- ошибки получения API-ключа;
- ошибки внешних запросов;
- сообщения о некорректных котировках;
- количество успешно обработанных акций.

При новом запуске приложения предыдущее содержимое файла заменяется.

## Тестирование

Тесты проекта написаны с помощью `pytest`. Для измерения покрытия исходного
кода используется плагин `pytest-cov`.

Тестовый набор проверяет все модули, находящиеся в каталоге `src`:

- `test_api_responses.py` — получение API-ключей, выполнение HTTP-запросов,
  обработка корректных и некорректных JSON-ответов, сетевых исключений;
- `test_currencies.py` — получение валютных курсов, проверка ответа API,
  расчёт обратных курсов, обработка настроек и ошибочных значений;
- `test_fields.py` — поиск по буквальным ключам и вложенным путям, работа с
  псевдонимами полей, загрузка пользовательских настроек;
- `test_processing_views.py` — выбор приветствия, загрузка и фильтрация
  транзакций по диапазонам `W`, `M`, `Y`, `ALL`, разделение расходов и
  поступлений, группировка по картам и категориям, расчёт кешбэка, сумм и
  количества операций, формирование топов и категории `Остальное`;
- `test_readers.py` — чтение Excel и JSON, пропуск пустых строк, обработка
  отсутствующих, повреждённых и неверно закодированных файлов;
- `test_stocks.py` — получение котировок акций, проверка ответа API,
  преобразование стоимости в другую валюту и обработка некорректных данных;
- `test_views.py` — формирование JSON-ответов страниц «Главная» и «События» и
  правильная передача рассчитанных сумм, количества операций и котировок.

Для категории `Остальное` предусмотрен отдельный регрессионный тест: он
проверяет, что суммы и количество транзакций категорий вне топа добавляются
ровно один раз.

Внешние HTTP-запросы изолированы с помощью объектов `Mock` и фикстуры
`monkeypatch`, поэтому для запуска тестов не требуются доступ в интернет и
настоящие API-ключи. Временные файлы создаются через фикстуру `tmp_path` и не
изменяют файлы проекта.

### Запуск тестов

Запустить весь набор тестов:

poetry run pytest
```

Запустить тесты одного модуля:

poetry run pytest tests/test_currencies.py
```

Запустить один тест:

```shell
poetry run pytest tests/test_stocks.py::test_get_stock_rates_returns_simplified_quotes
```

```shell
poetry run pytest -k "currency"
```

poetry run pytest --cov=src --cov-branch --cov-report=term-missing

Создать интерактивный HTML-отчёт о покрытии:
